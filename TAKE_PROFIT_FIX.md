# Исправление функции Take-Profit

## Проблема
Бот не ставил take-profit ордера, хотя позиции имели значительный PNL (например, ETH с +36.74%). 

### Причина проблемы:
1. **Неправильный расчет PNL**: Бот рассчитывал PNL локально на основе средней цены входа из файла, а не использовал реальный PNL от API Bybit
2. **Отсутствие синхронизации**: Локальные данные не соответствовали реальным данным на бирже
3. **Неточные данные**: Логи показывали PNL -0.21% для ETH, тогда как реальный PNL был +36.74%

## Исправления

### 1. Использование реального PNL от API Bybit
```python
# Получаем реальные позиции от API
response = session.get_positions(category="linear", settleCoin="USDT")
api_positions = response["result"]["list"]

for api_pos in api_positions:
    # Получаем реальный PNL от API
    unrealized_pnl = float(api_pos["unrealisedPnl"])
    position_value = float(api_pos["positionValue"])
    
    # Рассчитываем PNL в процентах от стоимости позиции
    pnl_percent = unrealized_pnl / position_value
```

### 2. Улучшенное логирование
- Теперь показывается реальный PNL в USDT и процентах
- Отображается средняя цена входа и текущая цена от API
- Более подробная информация для отладки

### 3. Проверка дублирующих ордеров
```python
# Проверяем существующие take-profit ордера
existing_tp_orders = get_existing_take_profit_orders(session, user_id, symbol)
```

### 4. Правильная логика trailing take-profit
- Триггер: PNL >= 15% → устанавливает take-profit на 10%
- Трейлинг: PNL 17% → take-profit на 12%, PNL 19% → take-profit на 14%
- Автоматическая отмена старых ордеров при обновлении уровня

## Результат
Теперь бот:
- ✅ Использует реальный PNL от API Bybit
- ✅ Правильно рассчитывает проценты PNL
- ✅ Автоматически ставит take-profit при достижении 15% PNL
- ✅ Обновляет take-profit при росте PNL (trailing)
- ✅ Не создает дублирующие ордера
- ✅ Подробно логирует все операции
